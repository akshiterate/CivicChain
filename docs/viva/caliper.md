# Viva: Caliper benchmarking (`caliper/`)

## What runs

Caliper manager + ethereum connector talk to the local Hardhat node over
WebSocket. Rounds in `benchmarkConfig.yaml`: submit-smoke (10), submit-load
(100), status-update (20). `smokeConfig.yaml` is the 5-tx wiring check.
Launched with `npm run bench` / `npm run bench:smoke` from inside `caliper/`.

## Files

- `networkConfig.json` — generated by `scripts/setupCaliper.js`: ws URL, one
  funded account, `contracts.CivicChain` with embedded ABI + live address +
  fixed gas. Generated because Caliper 0.5.0 cannot pass constructor args.
  Must be regenerated after every node restart.
- `workloads/submit.js` — sends `submitComplaint` via `this.sutAdapter.sendRequests`.
- `workloads/status.js` — reads `getTotalComplaints` (readOnly), then updates
  the newest ids backwards so reruns never collide with updated ones.
- `makeReport.js` — parses the log's result table and writes `charts.html`
  (tables + inline SVG bar charts), `report.md`, `results.csv`. No chart
  library, no new dependency.
- `results/2026-10-10/`, `results/2026-10-26/` — one folder per run: Caliper
  logs, Caliper's own `report.html`, plus the three generated files.

## Results (say these exact numbers)

Latest, 2026-10-26, full run 39.1 s: submit-smoke 10/0 @5.5 TPS (avg latency
0.02 s), submit-load 100/0 @20.2 TPS (0.01 s), status-update 20/0 @5.3 send /
5.2 throughput TPS (0.01 s). Chain read-back: 115 complaints, 20 In Progress,
95 Reported, 0 Resolved.

Earlier, 2026-10-10: same 10/0, 100/0, 20/0 and same 5.5 / 20.2 / 5.3 TPS.
Only max latency differed (0.06 vs 0.03 s) — millisecond noise.

Local automine only — meaningless for Sepolia.

## Honest war stories (say if asked)

- `http://` RPC is rejected by the connector (needs `ws://`); Hardhat serves both.
- Caliper's own `bind` (npm install web3) crashes on Windows (`spawn EINVAL`);
  skipped — web3 already present transitively.
- First workloads used ethers directly: txs mined but Caliper counted 0 and the
  round looped for thousands of phantom complaints. Rewritten through
  `sutAdapter.sendRequests`, which fires the counted/timed path.
- `npm run bench` originally passed `--caliper-network` instead of
  `--caliper-networkconfig`, so Caliper never received a network config and
  exited with `Network configuration file path is not set` before touching the
  chain. Fixed; the smoke results above were produced with the fixed script.
- One worker only: the connector tracks one account nonce; two workers would
  reuse nonces.
- Restarting `hardhat node` invalidates the deployed address: the next run
  reverts on every tx until `setupCaliper.js` is run again.
- Running the benchmark via PowerShell `2>` redirection shows "Exited with
  code 1" even on success — that is PowerShell turning Node's harmless
  `TimeoutNegativeWarning` on stderr into a NativeCommandError. Caliper's own
  exit code is 0 (`Benchmark successfully finished`).

## Likely questions

- "Throughput vs send rate?" — Practically equal here (local node mines
  instantly); status-update shows 5.3 send vs 5.2 throughput because the last
  transactions drain after the sending stops.
- "CPU/memory?" — Default observer gives tx stats only on this setup; no
  fabricated percentiles. Documented in `docs/benchmarking.md`.
- "How are the charts made?" — `caliper/makeReport.js` reads the numbers out of
  Caliper's log table and emits SVG `<rect>` bars; nothing is hand-typed.
