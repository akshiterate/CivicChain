# Viva: Caliper benchmarking (`caliper/`)

## What runs

Caliper manager + ethereum connector talk to the local Hardhat node over
WebSocket. Rounds in `benchmarkConfig.yaml`: submit-smoke (10), submit-load
(100), status-update (20). `smokeConfig.yaml` is the 5-tx wiring check.

## Files

- `networkConfig.json` — generated by `scripts/setupCaliper.js`: ws URL, one
  funded account, `contracts.CivicChain` with embedded ABI + live address +
  fixed gas. Generated because Caliper 0.5.0 cannot pass constructor args.
- `workloads/submit.js` — sends `submitComplaint` via `this.sutAdapter.sendRequests`.
- `workloads/status.js` — reads `getTotalComplaints` (readOnly), then updates
  the newest ids backwards so reruns never collide with updated ones.
- `results/` — real logs + HTML report from 2026-10-10.

## Results (say these exact numbers)

submit-smoke 10/0 @5.5 TPS, submit-load 100/0 @20.2 TPS, status-update 20/0
@5.3 TPS, avg latency ~0.01s. Local automine only — meaningless for Sepolia.

## Honest war stories (say if asked)

- `http://` RPC is rejected by the connector (needs `ws://`); Hardhat serves both.
- Caliper's own `bind` (npm install web3) crashes on Windows (`spawn EINVAL`);
  skipped — web3 already present transitively.
- First workloads used ethers directly: txs mined but Caliper counted 0 and the
  round looped for thousands of phantom complaints. Rewritten through
  `sutAdapter.sendRequests`, which fires the counted/timed path.
- One worker only: the connector tracks one account nonce; two workers would
  reuse nonces.

## Likely questions

- "Throughput vs send rate?" — Practically equal here (local node mines instantly).
- "CPU/memory?" — Default observer gives tx stats only on this setup; no
  fabricated percentiles. Documented in `docs/benchmarking.md`.
